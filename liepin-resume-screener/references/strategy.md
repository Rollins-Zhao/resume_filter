# 第一部分：boss-agent-cli 使用策略（BOSS 直聘）· 历史参考

> **当前决策：不使用。** 原因见文末《BOSS 通道决策记录》。保留此节以备将来复查。

## 〇、安装与前提（给部署者）

```bash
# 推荐安装方式（uv 秒级安装，自动隔离）
uv tool install boss-agent-cli

# 安装浏览器内核（仅用于用户主动登录 / 本地导出场景）
patchright install chromium

# 环境自检
boss doctor

# 登录（多级降级：本地浏览器 Cookie 提取 → CDP 复用真实 Chrome → patchright 扫码兜底）
boss login

# 验证登录态
boss status
```

- **命令真相源**：`boss schema`——所有能力、参数以它输出为准（不同版本间命令面有变化，执行前先查）。
- **输出协议**：所有命令输出结构化 JSON 信封 `{ok, data, pagination, error, hints}`，exit code 0/1。错误自带 `recovery_action`，按它执行恢复，不要自行发明修复动作。
- **反检测基础**：基于 patchright（Playwright 反检测分支）二进制级修补自动化标记 + 内置高斯分布请求延迟 + 指数退避重试。

## 一、操作间隔（必须随机化，严禁固定间隔）

- 翻页操作：每页之间等待随机 **12–22 秒**
- 查看职位详情：每个详情页之间等待随机 **10–25 秒**（详情页访问更敏感，间隔要更大）
- 搜索操作：每次搜索之间等待随机 **15–30 秒**
- 所有等待必须使用随机数，**严禁固定秒数**——固定间隔是最大的破绽
- 工具内置高斯延迟是第一层保护，编排层的随机 sleep 是第二层兜底，**两层都要有**

## 二、请求节流的正确配置

`--request-interval` 命令行参数不能默认假设存在（各版本命令面不同），节流按以下优先级落实：

1. **全局配置（首选）**：`~/.boss-agent/config.json` 中设置请求间隔、批量操作间隔
2. **命令行参数**：执行前用 `boss schema` 确认当前版本是否支持 `--request-interval`，支持则用随机区间（如 `--request-interval "12,22"`）
3. **编排层兜底**：无论 1、2 是否生效，Agent 在每条命令之间必须插入随机 sleep——**这是唯一保证存在的节流层**

## 三、操作红线（重要：阻断机制已变化，责任在使用者）

当前版本已移除模式级 `COMPLIANCE_BLOCKED` 自动阻断（旧文档中"assisted 模式会自动拦截打招呼"的描述已过时）。现行状态：

| 操作 | 现状 | 策略要求 |
|---|---|---|
| 招聘者侧候选人个人数据链路（hr candidates 等） | 工具默认阻断 | 尊重阻断，**不得尝试绕过** |
| 求职者侧 greet（打招呼）/ apply（投递） | 命令可用，不会被拦 | ⛔ 默认禁止自动执行；如用户明确要求，仅允许逐条执行且每条需用户确认，**严禁批量循环** |
| 联系方式交换、消息批量群发 | —— | ⛔ **绝对禁止，无任何例外** |
| search / detail / recommend / export / watch 等只读+本地操作 | 正常可用 | ✅ 主要工作区，按频率纪律执行 |

**敏感触达类操作必须引导用户到 BOSS 直聘官网/App 手动完成。**

## 四、总量控制

- 单次运行最多翻 **10 页**，查看最多 **30 个**职位详情
- 单日对同一账号的操作不超过 **200 次**请求
- `boss watch`（增量监控）频率不超过每天 **1–2 轮**
- **触发以下错误立即停止，不得重试**：
  - `RATE_LIMITED`（限流）
  - `AUTH_EXPIRED`（登录态失效）
  - `NETWORK_ERROR`（网络异常）
  - `code 36`（平台风控错误码）——出现即代表已被风控盯上，停止一切操作并通知用户人工检查账号
- 错误处理统一走 JSON 信封的 `recovery_action` 字段；执行恢复动作前先向用户报告

## 五、模拟人类行为

- 每次操作前用 `boss status --live` 确认登录态有效（低频只读探测，不要高频调用）
- 不要连续执行同类操作，在搜索和查看详情之间穿插随机休息
- 多平台功能（`--platform zhipin|zhilian|qiancheng`）切换时同样遵守间隔纪律，配额按账号分别计算
- 登录优先走 Cookie 提取或 CDP 复用真实浏览器，减少额外扫码次数（**频繁扫码本身是风控信号**）

## 六、紧急停止

遇到以下情况，立即终止所有自动化操作并通知用户：

- 账号被登出或提示异常登录
- 连续收到 3 次以上风控相关错误（含 code 36）
- 平台页面结构异常导致命令失败
- 出现任何"账号异常，请联系客服"类弹窗的报告

## 七、本地数据纪律

- 候选池/职位数据用 `boss shortlist`（本地标签、备注、对比）管理，不外传
- 导出文件（`boss export`）仅本地保存，不得用于公开分享或二次分发

# 第二部分：liepin-cli 使用策略（猎聘）· 当前执行依据

## 〇、安装与前提（给部署者）

```bash
# 要求：Node.js ≥ 20，本机已安装 Chrome/Chromium
npm install -g @viyzhu/liepin-cli

# 登录招聘者端（弹出浏览器扫码；登录会自动切有头模式，cookie 持久化在 ~/.liepin-cli/user-data）
liepin login

# 可选：注册为 Agent Skill（复制到 ~/.agents/skills/liepin-cli/）
liepin skill install
```

> 本机注意：`npm install -g` 会被策略拦截，改用托管工作区安装（见 SKILL.md 步骤 1）。

**命令清单**（全部输出结构化文本，供 Agent 解析）：

| 命令 | 功能 | 风险级 |
|---|---|---|
| `liepin search <关键词> --city --experience --limit --json` | 搜索人才 | 低（只读） |
| `liepin resume <resume_id>` | 简历详情 | 低（只读） |
| `liepin recommend` / `liepin talent` | 推荐候选人 / 人才库 | 低（只读） |
| `liepin joblist` | 职位列表 | 低（只读） |
| `liepin chatlist` / `liepin chatmsg <imId>` | 聊天列表 / 聊天记录 | 低（只读） |
| `liepin greet <resume_id> --ejobId --message "..."` | 主动打招呼 | **高（触达）** |
| `liepin quit` | 关闭常驻浏览器 | — |

**退出码语义**（脚本按此分支，不要解析报错文案）：

- `0` 成功
- `1` 一般错误
- `2` 登录态失效 → 重新 `liepin login`
- `3` 触发风控/安全异常 → **立即停止全部自动化**，通知用户人工在浏览器完成验证

## 一、操作间隔（必须随机化，严禁固定间隔）

liepin-cli **没有 `--request-interval` 类参数，也没有内置节流**——全部间隔由编排层（Agent/脚本）实现：

- 搜索之间：随机 sleep **15–30 秒**
- 逐份查看简历之间：随机 sleep **10–25 秒**
- 翻页之间：随机 sleep **12–22 秒**
- 所有 sleep 用随机数，**严禁固定值**
- 搜索与查看之间穿插更长随机休息（**30–90 秒**），不要连续同类操作

## 二、操作红线（比 BOSS 更严——因为这个工具完全没有自动阻断）

liepin-cli 的 `greet` 命令**完全开放、无任何护栏**，合规责任 100% 在编排方：

- ⛔ **默认禁止自动执行 `liepin greet`**。所有打招呼必须由用户在猎聘官网/App 手动完成（Agent 可生成话术供复制）
- ⛔ **严禁批量触达循环**、**严禁自动交换联系方式**
- ✅ **推荐架构：只读筛选 + 人工触达**——Agent 负责 `search → resume → 打分排序 → 输出推荐报告`（含匹配理由和建议话术），用户自己在平台完成收藏和沟通
- ✅ 通知走独立通道（飞书 webhook / 邮件），与猎聘完全解耦，零额外风险

## 三、总量控制

- 单次运行：搜索 ≤ **10 页**、简历详情 ≤ **30 份**
- 单日请求 ≤ **200 次**
- 如做每日增量扫描（定时任务），本地记录已处理的 `resume_id` 去重，**只碰新简历**，避免重复访问同一候选人
- 频率参照真人 HR 行为基线：**每天看 50–100 份简历是正常区间，超过 200 份就是"批量抓取"信号**

## 四、环境与风控特性（猎聘专项）

- **CDP 检测**：猎聘安全脚本会在页面加载瞬间检测 CDP 会话的 Runtime 域，命中即清空页面为 `about:blank`。工具 0.2.4+ 用 `safeGoto` 规避（导航期间临时关闭 Runtime）——保持工具为最新版本，遇到 about:blank 立即升级
- **境外 IP 全拦**：猎聘封锁境外 IP。跑命令前先关 VPN/代理（含 Clash TUN 等整机隧道），或把 `*.liepin.com` 设为直连
- **浏览器默认无头**：登录（扫码）会自动切有头。想全程可见：`LIEPIN_HEADLESS=false`；调试用 `LIEPIN_DEBUG=true`
- **浏览器跨命令常驻**（CDP 端口 53471）：命令结束不断开，下条命令复用同一登录态；跑完用 `liepin quit` 释放内存
- **Chrome 找不到时手动指定**：`CHROME_PATH="C:\Program Files\Google\Chrome\Application\chrome.exe"`

## 五、模拟人类行为

- 每批操作前先跑一条低成本命令（如 `liepin joblist`）验证登录态，出现退出码 2 先重新登录
- 推荐用 `liepin recommend`（平台主动推荐的行为）和 `liepin search` 穿插，比纯 search 扫库更像真人
- 每天操作时段尽量集中（如上午 9–11 点），避免 24 小时连轴转

## 六、紧急停止

遇到以下情况，立即终止所有自动化操作并通知用户：

- 退出码 3（风控触发）——立即停止，人工在浏览器完成验证后再说
- 账号被登出、提示异常登录
- 连续 3 次一般错误（退出码 1）
- 页面被清空为 `about:blank` 且升级工具后仍复现

# 附录：风险事实清单（使用前必读）

## 平台规则原文（BOSS《职位信息发布规则》）

- 任何用户不得使用任何招聘管理系统/插件/外挂/工具/ATS 访问或接入 BOSS 直聘系统——第三方 CLI 在条款上属于违规
- 平台"可以依据本规则直接采取相关措施，并**视情节严重程度选择是否通知用户**"——实践中通常渐进处罚，但平台**保留不通知直接处理的权利**

## 实际处罚梯度（真实案例归纳）

| 梯度 | 触发条件 | 典型表现 |
|---|---|---|
| 轻 | 首次被检测到自动化特征 | "账号异常"弹窗、功能限制 30 分钟–24 小时 |
| 中 | 反复触发、持续高频 | 限流、禁言、部分功能冻结 |
| 重 | 欺诈、骚扰候选人、**批量索取简历**、虚假职位 | 永久冻结、关联账号连坐、冻结企业主体 |

**关键结论**：决定处罚等级的主要是**行为危害（触达骚扰）**，而非"被检测到自动化"本身。只读操作最坏结果一般是限流；**自动触达才通向重罚**。这就是"只读 + 人工触达"架构的根本依据。

# BOSS 通道决策记录（2026-09-10）

## 调研结论

检索到 2 个具备招聘者能力的 BOSS CLI：

1. **kabi-boss-cli**（github.com/yang1996202-cpu/boss-cli，873★，Apache-2.0）
   - 只读：`recruiter search / recommend / resume / geek / export / jobs / labels`
   - 高危：`greet`、`batch-view`（批量查看会向候选人发"被查看"通知）、`exchange-phone`、`exchange-wechat`、`reply`、`invite-interview`、`request-resume`、`mark-unsuitable`
   - 装法：PyPI 发布版**无 recruiter 功能**，需从 GitHub 源码安装
2. **@joohw/boss-cli**（boss-cli.com，v0.3.4，GPL-3.0，npm）：定位"专为 HR 和招聘团队"，CDP 实现，含批量消息发送、一键打招呼

## 为何最终不使用

1. 与策略红线「招聘者侧候选人数据链路工具默认阻断——**尊重阻断，不得尝试绕过**」直接冲突（换工具实现同一能力即绕过）
2. 招聘者账号实名 + 企业绑定，违规处罚为**企业主体连坐**（全公司 BOSS 招聘能力冻结），量级远重于猎聘限流
3. 条款明确禁止第三方工具接入，BOSS 反自动化投入为行业最高
4. 商业事实：BOSS 99.4% 收入来自企业端，"企业看简历/联系候选人"本身即其付费商品。用第三方工具抓取即触碰其核心收入
5. **实测触发风控**：登录环节即被平台提醒（`__zp_stoken__` 缺失导致"环境异常"，属风控信号）

**结论：BOSS 通道全面放弃，资源集中于猎聘。**
